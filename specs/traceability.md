## 2. Deviations documented against Assignment 1

1. **Complete removal of online payment (Stripe) and escrow:** To focus the 4-week prototype on the core business value (map-based discovery without GPS and basket negotiation without stock management), the Stripe integration (`C1-F5`, `C3-F4`, `C3-F5`, `C1-NF2`) has been deferred.
2. **Internal notifications instead of external e-mails:** `C3-F2` is implemented through a notification bell persisted in SQLite rather than SMTP e-mail delivery. The server architecture nevertheless uses a `NotificationChannel` interface allowing an e-mail connector to be added later.
3. **Automatic geocoding on farm creation:** In addition to `C2-F1`, the server automatically derives the farm's GPS coordinates through the Swiss `geo.admin.ch` API (with a fallback to Nominatim) from the address entered by the producer.
4. **Local storage of banners:** Banner photos (`C2-F1`) are uploaded via `multer` and served from the server's local file system (`backend/uploads/`), without resorting to external cloud storage.
5. **Basket prices are frozen at request time:** `basket_items.unit_price_snapshot` records the catalogue price when the client orders. This is stricter than A1's wording, where the final price was implicitly the current one; it prevents a producer from retroactively changing an existing request (`C3-F3`).
6. **Buying does not require the `CLIENT` role (`ADR-08`):** A1 implies a distinct consumer actor, but nothing in the flow needs one. Producers and administrators buy food too, so checkout requires authentication only; ordering from one's own farm is refused (`SELF_ORDER`).
7. **Baskets do not require an account (`ADR-10`):** A1 assumed a registered consumer for every basket. In practice requiring an e-mail address to buy is friction users do not expect from a shop, and no part of the flow needs an identity, so an anonymous device session is issued on the first order and an account becomes a convenience (e-mail reminders) rather than a requirement. The consequence is explicit: baskets and notifications are tied to the **device**, so they do not follow the visitor to another browser. A 30-day cookie is generous for fresh produce, and cross-device sync was judged not worth the complexity here.
